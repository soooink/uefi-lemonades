Implementation contract:
GPIO36/37 CTL and OUT bit1 implement software open-drain I2C:
OUT stays0, OE1 sinks low, OE0 releases. High is never actively driven.
GPIO39, GENI/clock/IRQ registers remain read-only or untouched.
First snapshot includes SE13 40/48/64/68/7c/908 and GPIO36/37/38/39/69 CTL/IO.
No takeover if GENI is busy or released SDA/SCL are not high.
If reset38/rail69 are not driven high, guarded initialization finds exactly
one PMIC type51/model27 on known even SIDs0/2/4/8/a; its secondary SID is
even+1. Candidate LDO1 must read this handset's observed type04/subtype71
and already be set to1800mV. No SPMI register is written by touch.
If aggregate ENABLE4046 is exactly0 and READY4008 bit7 is clear, UmiRpmhLib
may send one ACTIVE ldoc1 enable=1 request. It dynamically resolves the exact
cmd-db resource; no numeric accelerator address is guessed. See that library's
SOURCES.txt for RSC/DB origins, strict guards and bounded completion protocol.
Ready4008 bit7 and actual voltage4042/43=1800mV must then be observed.
After15ms, GPIO69 is driven high and reset38 held low10ms then driven high.
The source reset GPIO sequence is in ftsCore.c85, power order in fts.c6803.
Attempt12 established PM8150A at SID4/model27 and LDO1 at SID5/type04/subtype71,
set1800mV, ENABLE0, READY03, actual0. Direct SPMI enable was refused because
no EE0-owned write channel exists; there is no bypass or direct-write fallback.
The RPMh experiment requests only enable, leaving voltage/mode/other resources
untouched. Existing inherited already-enabled supplies do not acquire a vote.
Supply state inherited across boot is unknown until observation; normal
Android runtime state does not establish the state inherited from ABL.

At TPL_CALLBACK only: combined92/86/repeated-START93/read8/STOP, last byte
NACK. A valid ACKed FIFO record permits only normal volatile A0 00 01 scan.
Four records maximum per20ms callback; one transfer limit8ms and one SCL
stretch limit500us, plus one bounded STOP on error. The driver cancels its
timer and restores owned pins/power on transport/protocol/preflight errors.
After this driver's hardware reset, NACK is tolerated only within100ms while
awaiting READY03. This100ms NACK policy is our bounded bring-up strategy;
Linux itself retries each transfer3 times with2ms gaps and up to3 resets.
No all-address scan, bus recovery pulses, calibration, firmware burn or
flash-save command is performed. Normal-operation errors have no retry loop.

One finger/glove is tracked; no palm/hover/pen. A second contact, unsupported
type during an active gesture, invalid XY, malformed record or queue overflow
cancels the gesture and disables touch for this boot. Coordinates are native
portrait0..1079/0..2339. Display rotation must be applied by the consumer.
Motion can recover a missed enter; a real leave keeps the last valid XY.
An ordered32-entry queue preserves a tap's down/up when read in one batch.
Cancellation clears that queue: it never synthesizes an EFI_SUCCESS tap-up.
WaitForInput signals cancellation once and GetState returns EFI_DEVICE_ERROR.
The consumer must clear Down/Eligible/ArmedRow on that status and must not
activate a row. Other input protocols remain available. A controller-ready03
record also clears the queue and signals cancellation, but is recoverable:
volatile normal scanning resumes; cancellation is delivered before any
post-reset pointer samples. Fatal errors keep GetState returning DEVICE_ERROR.

WaitForInput only checks the queue/cancellation at TPL_NOTIFY. Reset is a
software cancellation of pointer state, with no chip GPIO reset.
ExitBootServices cancels polling and restores saved CTL/output latches for
GPIO36/37 and, if changed, GPIO38/69. L1 is restored only if this driver
enabled it: cleanup sends RPMh enable=0 to withdraw its current DRV2 request.
This is not an exact restoration of an unknown inherited DRV vote; other DRVs
remain independently aggregated. Busy/unconfirmed completion cannot be
overwritten; the library retains its slot/snapshot and outstanding marker so
later cleanup can retry. Error completion while idle is reclaimable, but a
failed disable retains the possibly-effective enable marker.
An inherited running controller's power is retained. The next OS owns its
reset/mode programming.
