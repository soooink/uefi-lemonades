LemonadesRpmhLib: independent BSD-2-Clause-Patent implementation, no vendor blob.

This experiment sends only an ACTIVE enable request for the exact padded
cmd-db key ldoc1 on this handset's APPS RSC DRV2. It has no arbitrary address
or voltage/mode API. The caller first requires PMIC model27, LDO type04,
observed subtype71, an existing 1800mV setting and aggregate software-enable0.
Already-ready inherited supplies do not acquire an RPMh request.

Ownership, completion and cleanup contract:
- Both ACTIVE0/1 must be idle and have no pending IRQ. Chosen slot must have
  CMD_ENABLE=0,WAIT=0 and no CONTROL bits other than AMC mode16/trigger24.
  Attempt13 observed both CONTROL=0 with idle/empty slots, so attempt14
  initializes AMC mode using the hardware sequence above. Other modes reject.
- Snapshot only the selected slot's modified command0/WAIT/CONTROL and its
  IRQ-enable bit. No SLEEP/WAKE/control TCS, ownership or PMIC register writes.
- Clear any old trigger24 and then mode16 before installing a command. Enable only our IRQ
  bit, submit length8|WRITE|RESP_REQ, wait-for-completion1 and command-enable1,
  then enable mode16 with readback before triggering. CPU IRQ state is
  saved/disabled throughout each bounded call.
- Fresh own IRQ plus idle is terminal. issued8+complete16 also required for
  success. An idle/error completion clears inflight, returns DEVICE_ERROR,
  and retains the possibly-effective enable marker; later cleanup can retry.
- One20ms budget per public transaction; MMIO writes have readback checks.
  An error masks only our TCS IRQ within a separate1ms bound before restoring
  CPU IRQ state. Mask failure is logged; no busy command is overwritten.
- Busy/unconfirmed timeout retains inflight and the original snapshot.
  Subsequent cleanup waits for terminal idle+IRQ before touching the slot.
  Even idle+old CMD_STATUS success without fresh IRQ cannot prove completion.
- Completed/untriggered idle slots restore command0/WAIT, clear CMD_ENABLE,
  and restore CONTROL with trigger24 forced clear. Old triggers are NEVER
  replayed. IRQ_CLEAR is W1C for our bit only; IRQ_ENABLE restoration changes
  only our bit. Failed restoration remains outstanding and retryable.
- Command register restoration does not retract resource state. Cleanup sends
  ldoc1 enable data0, retracting our current DRV2 request. Other DRVs aggregate
  independently. This DOES NOT reconstruct an unknown inherited DRV2 vote.
  Physical aggregate-enable0 is an experiment guard, not a read of that vote.
- No runtime sleep/wake/solver support or third-party DRV2 concurrent client
  arbitration is implemented. Busy/pending/unsupported states are rejected.
